## Install

You need **Python 3.11 or newer** — check with `python --version`.

<Tabs syncKey="installer">
<TabItem label="pip">

```bash
python -m venv .venv
source .venv/bin/activate       # Windows: .venv\Scripts\activate

python -m pip install buraq
```

</TabItem>
<TabItem label="uv">

```bash
uv venv
source .venv/bin/activate       # Windows: .venv\Scripts\activate

uv pip install buraq
```

No uv yet? `curl -LsSf https://astral.sh/uv/install.sh | sh` on macOS and Linux,
`powershell -c "irm https://astral.sh/uv/install.ps1 | iex"` on Windows.

</TabItem>
</Tabs>

Activating matters: it is what makes `buraq` the one you just installed rather
than whichever your `PATH` finds. That environment is also where your project's
own packages go.

```bash
buraq --version
# Buraq 1.6.0
```

## Create a project

```bash
buraq startproject myproject
cd myproject
```

You get `config/` (settings and URLs), `main.py`, `manage.py`, a `pyproject.toml`
listing Buraq, and a `.env` holding a freshly generated `SECRET_KEY`.

That is all it does — no environment, no install. You are already in one, which
is how you ran the command.

## Run it

```bash
buraq migrate
buraq runserver
```

Your project is on `http://127.0.0.1:8000`, and the auto-generated API docs are
at `/api/docs`.

## Adding your own packages

Into the same environment as Buraq:

```bash
python -m pip install httpx     # or: uv pip install httpx
```

Record them in the project's `pyproject.toml` so the next person gets them too.

## Database drivers

SQLite works out of the box — `aiosqlite` is bundled, nothing to install. For
anything else, add the driver **inside the project**:

<Tabs syncKey="installer">
<TabItem label="uv">

```bash
uv add "buraq[postgres]"         # PostgreSQL
uv add "buraq[mysql]"            # MySQL / MariaDB
```

</TabItem>
<TabItem label="pip">

```bash
python -m pip install "buraq[postgres]"    # PostgreSQL
python -m pip install "buraq[mysql]"       # MySQL / MariaDB
```

</TabItem>
</Tabs>

Then point `DATABASE_URL` at it in `config/settings.py` — see
[Settings](/docs/getting-started/settings).

## Troubleshooting

**`buraq: command not found`** — the environment is not activated. Activate it,
or use `python -m buraq`. Running things as `python -m …` is why the commands
above do: it uses whichever Python you invoked, where a bare `pip` or `buraq`
uses whatever your `PATH` happens to find first. If you installed with `uv tool install`, run
`uv tool update-shell` and open a new terminal.

**`ModuleNotFoundError`, or `buraq` behaving like a version you do not have** —
you are in a different environment from the one you installed into. This prints
which Buraq is actually running:

```bash
buraq shell -c "import buraq; print(buraq.__file__)"
```

A `site-packages` path under your project's `.venv` is what you want. Three
things commonly put you somewhere else: not activating, so the command comes
from your `PATH`; `uv tool install` or `pipx`, which hold Buraq in an
environment of their own with nothing of yours in it; and `uv run` inside a
project, which uses that project's own environment and installs what its
`pyproject.toml` declares from the index.

**`No pyproject.toml found in current directory or any parent directory`** —
from `uv add buraq`. `uv add` adds a dependency to a project that already
exists, and you do not have one yet. Use `uv pip install buraq`.

**You want the environment made for you** — `buraq startproject myproject
--install` creates a `.venv` in the project and installs into it, with `uv` when
it is there and `venv` + `pip` when it is not.

**You want the project somewhere else** — name a directory second:
`buraq startproject myproject blog_folder`. Files land directly in it. `--dest`
does the same thing.
