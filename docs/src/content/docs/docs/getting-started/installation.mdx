## The short version

<Tabs syncKey="installer">
<TabItem label="pip">

```bash
python -m venv .venv
.venv\Scripts\activate        # Windows; source .venv/bin/activate elsewhere
pip install buraq

buraq startproject myproject
cd myproject
buraq migrate
buraq runserver
```

Works on any machine with Python. Slower installs than uv, nothing else lost.

</TabItem>
<TabItem label="uv">

```bash
uv venv
.venv\Scripts\activate        # Windows; source .venv/bin/activate elsewhere
uv pip install buraq

buraq startproject myproject
cd myproject
buraq migrate
buraq runserver
```

Needs uv — if `uv` is not a command on your machine yet, it is
[one line away](#requirements), or use the pip tab.

</TabItem>
</Tabs>

Your project is on `http://127.0.0.1:8000`. Everything below explains those
lines.

:::note[The environment is yours]
`buraq startproject` writes files. It does not create a virtualenv or install
anything, because reaching the command at all means Buraq is installed and
importable — the project runs in whatever environment you are already in,
whether that is a venv, conda, Poetry or a container. Your own packages go in
that same environment.

Pass `--install` if you would rather it made a `.venv` in the project and
installed into that.
:::

## Requirements

- **Python 3.11 or newer** — check with `python --version`, and install from
  [python.org/downloads](https://www.python.org/downloads/) if it reports lower
- **uv** — recommended, and a one-line install

uv installs far faster than pip and manages a project's environment and lockfile
for you. Nothing here requires it — `buraq startproject` writes files and does
not touch your environment, so whichever tool you already use is the right one.

```bash
# macOS / Linux
curl -LsSf https://astral.sh/uv/install.sh | sh

# Windows (PowerShell)
powershell -c "irm https://astral.sh/uv/install.ps1 | iex"
```

Other methods are in [uv's own guide](https://docs.astral.sh/uv/getting-started/installation/).

:::note[Prefer to stay with pip?]
Everything works with pip — it ships with Python, and every step on this page has
a pip tab. You give up install speed and the managed lockfile, nothing else.
:::

## 1. Make an environment and install Buraq

Your project's packages need somewhere to live, and so does Buraq. One
environment holds both:

<Tabs syncKey="installer">
<TabItem label="pip">

```bash
python -m venv .venv
.venv\Scripts\activate        # Windows
source .venv/bin/activate      # macOS / Linux

pip install buraq
```

</TabItem>
<TabItem label="uv">

```bash
uv venv
.venv\Scripts\activate        # Windows
source .venv/bin/activate      # macOS / Linux

uv pip install buraq
```

</TabItem>
</Tabs>

Check it worked:

```bash
buraq --version
# Buraq 1.6.0
```

:::note[Installing it globally instead]
`uv tool install buraq` or `pipx install buraq` put the command on your `PATH`
without an environment, which is convenient for trying Buraq out. It is not
enough to build with: the tool's environment holds Buraq and nothing of yours,
so the first package your own code imports will not be there. Make an
environment as above when you start writing anything.
:::

:::caution[Not `uv add buraq`]
`uv add` adds a dependency to a project that already has a `pyproject.toml`, and
you do not have one yet — it fails with `No pyproject.toml found in current
directory or any parent directory`. Use `uv add buraq` only to add Buraq to an
existing project.
:::

## 2. Create a project

```bash
buraq startproject myproject
cd myproject
```

This writes files and nothing else — no environment, no install. You are already
in one, which is how you ran the command.

You get `config/` (settings and URLs), `main.py`, `manage.py`, a `pyproject.toml`
listing Buraq, and a `.env` holding a freshly generated `SECRET_KEY`.

## 3. Run it

```bash
buraq migrate
buraq runserver
```

Your project is on `http://127.0.0.1:8000`, and the auto-generated API docs are
at `/api/docs`.

## Adding your own packages

They go in the environment from step 1, the same as Buraq:

```bash
pip install httpx          # or: uv pip install httpx
```

Record them in the project's `pyproject.toml` so the next person gets them too.

## Database drivers

SQLite works out of the box — `aiosqlite` is bundled, nothing to install. For
anything else, add the driver **inside the project**:

<Tabs syncKey="installer">
<TabItem label="uv">

```bash
uv add "buraq[postgres]"         # PostgreSQL
uv add "buraq[mysql]"            # MySQL / MariaDB
```

</TabItem>
<TabItem label="pip">

```bash
pip install "buraq[postgres]"    # PostgreSQL
pip install "buraq[mysql]"       # MySQL / MariaDB
```

</TabItem>
</Tabs>

Then point `DATABASE_URL` at it in `config/settings.py` — see
[Settings](/docs/getting-started/settings).

## Troubleshooting

**`buraq: command not found`** — the environment is not activated. Activate it,
or use `python -m buraq` in place of `buraq`. If you installed with
`uv tool install`, run `uv tool update-shell` and open a new terminal.

**`ModuleNotFoundError` for a package you installed** — you are in a different
environment from the one you installed into. `buraq shell -c "import buraq;
print(buraq.__file__)"` prints where the running Buraq is being read from.

**You want the environment made for you** — `buraq startproject myproject
--install` creates a `.venv` in the project and installs into it, with `uv` when
it is there and `venv` + `pip` when it is not. Without the flag the project is
files only, and runs in whatever environment you are already using.

**The `--install` step failed** (no network, a blocked index) — the project files
are still correct. `buraq startproject` prints the one command left to run; run
it from inside the project.

**You want the project somewhere else** — name a directory second:
`buraq startproject myproject blog_folder`. Files land directly in it. `--dest`
does the same thing.
